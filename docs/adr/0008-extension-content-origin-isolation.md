# 0008-扩展内容与宿主数据必须不同源：资产作用域收紧 + 扩展独立协议

> **2026-09-23 安全修订**：下文保留初次迁移背景；当前每个扩展使用 `http://xhub-ext.e-<id 摘要>.localhost` 独立来源。共享 `asset` 作用域只保留图标、壁纸和剪贴板图片，不再包含已安装或开发扩展目录；扩展图标也走独立协议。内容协议拒绝配置、凭据、数据库、日志、后端目录与元数据，并校验规范化后的路径，防止目录内链接绕过。宿主桥同时核对窗口与来源，回复绑定原来源；iframe 沙箱禁止弹窗、顶层导航和表单，内容 CSP 按网络权限放行 HTTPS。网络权限撤销后重建 iframe。跨扩展请求使用宿主分配的独立编号并核验响应窗口，避免编号冲突和伪造回复。

> 来源变更会让直接使用浏览器 `localStorage` / `IndexedDB` 的扩展暂时看不到旧来源数据；旧数据未删除，桥 `storage.*` 不受影响。Node service 仍遵循 ADR 0007 的信任边界。代理要求随机令牌与匹配的 Origin，停止服务时撤销令牌；这不代表后端进程具有操作系统沙箱。

> **状态：已实施**（决策于「扩展市场开放给第三方开发者」设计讨论 2026-09；两部分已于 2026-09-12 落地，验收见 `docs/open-market-client-plan.md` 的 T0.3）。

资产协议（asset protocol）是宿主把本地文件喂给 WebView 的通道：扩展入口 HTML 先写入 `<扩展目录>/.xhpack/<surface>.html`（为了让入口的相对资源同源加载，见 `extension.rs` 内注释），再由前端 `convertFileSrc` 换成 `http://asset.localhost/...` 作为 iframe src。问题出在**作用域是全局单例**，而它的允许范围是 `$APPDATA/**` 加上整个数据根（`tauri.conf.json` 的 `assetProtocol.scope` 与 `lib.rs` 启动时的 `allow_directory(data_root)`）。

三者叠加的后果：**扩展 iframe 与用户数据文件同源，且作用域允许访问整个数据根**——扩展里一行 `fetch` 就能取走 `xhub.db`（笔记、待办、剪贴板、AI 对话全在其中）与 `app.json`，**完全绕开桥 API 的权限系统**。这不是"权限声明没写全"，而是机制漏洞：`data:read` 这类权限门只管桥 API，管不住文件协议。在扩展全部出自第一方时它无害；一旦开放第三方提交，等于把「读取用户全部数据」发给每一个过审作者。

因此决定分两步：

1. **立即收紧资产作用域**：不再允许整个数据根与整个 `$APPDATA%`，改为白名单子目录（扩展目录、图标、壁纸、笔记图片、剪贴板图片、市场缓存），并显式排除数据库（含 WAL/SHM）、`app.json` 与日志目录。
2. **扩展内容改用独立协议**（`xhub-ext://`，宿主已有 `xhub-note` 自定义协议的先例）：扩展入口与其相对资源都由该协议服务，扩展的 origin 从此是 `xhub-ext.localhost`，而用户数据仍在 `asset.localhost` —— **两者跨源，扩展连数据文件的门牌号都找不到**。这一步是接收第一个第三方扩展的硬前置。

**被否方案**：①**只做第 1 步**——默认不安全：将来任何新增数据文件只要落进白名单目录就重新变成可读，安全性依赖"记得改配置"；②**只做第 2 步**——在自定义协议落地之前漏洞一直敞开，而第 1 步成本极低；③**把敏感数据移出扩展可读范围并靠 ACL 保护**——同一用户下的两个进程携带相同用户 SID，DACL 无法区分它们。

**代价（接受）**：扩展自身的 `localStorage`/`IndexedDB` 因 origin 变更清零一次（走桥 `storage.*` 的数据不受影响）；加载链路要改（`read_extension_entry` 的临时文件写盘逻辑与前端 URL 构造）；自定义协议必须自己维持"入口与相对资源同源"这一语义（这正是当初写 `.xhpack` 临时文件的原因，不能退回 `srcdoc`）。

**落点与验收**：改完后用一个测试扩展 `fetch` 数据根下的数据库路径，**必须返回 403/失败**；同时确认扩展自身的入口、相对资源与桥 API 全部照常工作。本 ADR 只覆盖 **web 扩展**（iframe 内容）：service 扩展的 Node 子进程以当前用户身份直接读写文件系统，与同源无关，其信任模型见 `0007-third-party-extension-trust-model.md`。
